# D-001：被中断的用户态任务仍属于用户态任务

## 背景

用户态执行流被内核级中断打断后，有三种处理方式：转成内核任务、创建内核影子任务、仍保留为用户态任务。这个选择决定任务类型、调度器归属、中断上下文位置和恢复路径。

## 决策

- 被中断的用户态任务仍是用户态任务，`Task::is_kernel()` 保持 `false`。
- 任务仍属于其进程的用户调度器，不进入内核调度器。
- 中断上下文保存在该用户任务的 TCB 中，不放在独立的内核任务里。
- 中断上下文由内核在 trap 入口/内核态保存；用户调度器选中该任务后，进入内核，由内核恢复。

## 替代方案

- **转成内核任务**：内核调度器会混入用户任务，需要类型转换和恢复后的反向转换。
- **创建内核影子任务**：需要维护用户任务与影子任务的对应、生命周期和唤醒关系，破坏用户/内核任务解耦。
- **把用户任务放进内核调度器**：违反“内核调度器只含内核任务”，调度器仍需处理用户任务多态。

## 后果

- OS 需要同时处理“中断上下文保存在用户任务 TCB”和“保存在内核任务 TCB”两种情况。
- OS 需要提供“从内核恢复用户态任务中断上下文”的接口；用户调度器只负责选择和发起陷入内核。
- 用户调度器选中中断上下文任务时，多一次进入内核的路径；换来内核调度器的任务类型纯净和用户/内核任务解耦。
- 具体路径、不变量和接口细节在设计中展开，不在本 ADR 重复。
