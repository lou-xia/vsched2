#数据结构修改

把要求操作系统实现的接口也作为数据结构的一部分

## 任务

| 名称与用途 | 是否现有 | 是否需要修改 | 修改后是什么样 |
|---|---|---|---|
| `Task`：由适配的操作系统定义完整TCB | 是 | 是 | 补充 action、上下文类型及等待唤醒所需接口；需要进一步考虑内核任务与用户任务的TCB如何保存 |
| `TaskState`：记录任务运行状态 | 是 | 否 | \ |
| `state` 等状态相关：查询、原子修改状态 | 是 | 是 | 状态转换由调度器完成，只保留读状态的接口 |
| `Action`：表达主动让权进入调度的原因 | 否 | \ | 表达让出、等待、退出等主动进入调度时的原因，Trap 时不考虑 |
| `is_coroutine()` 改名 `context_type()`：查询当前恢复方式 | 是 | 是 | 扩充为判断上下文类型（协程上下文、线程上下文、中断上下文），用于在恢复上下文时区分恢复方式 |
| `poll()`：运行协程 | 是 | 否 | \ |
| `register_waker`：注册waker，让用户任务使用调度器的waker | 否 | \ | 向用户任务提供一个waker，用户任务在poll时的ctx内存储这个waker |
| `resched()` 改名 `save_thread_context`：保存线程现场并进入调度入口 | 是 | 是 | 增加action操作 |
| `restore_context()` 改名 `restore_thread_context()`：恢复任务现场 | 是 | 是 | 只能恢复能够在用户态恢复的线程，即恢复线程上下文 |
| `priority()`：查询任务优先级 | 是 | 否 | \ |
| `pid / is_kernel`：地址空间id与任务特权级 | 是 | 否 | \（之前实现里有混用情况，需要分清） |
| `dealloc()`：释放退出任务 | 是 | 是 | 补充action，此外还需要检查出队列和释放锁 |
| 上下文及嵌套关联：保存被中断执行过程 | 具体结构由OS实现，目前想法是用vec储存 | \ | 表达顶层现场、下层未完成过程、引用的栈及交接目前存在问题，需要进一步考虑 |

## trap 相关

| 名称与用途 | 是否现有 | 是否需要修改 | 修改后是什么样 |
|---|---|---|---|
| `TrapInfo::from_task()`：保存 Trap 信息 | 是 | 否 | \ |
| `TrapInfo::handle()`：处理 Trap | 是 | 是 | 只区分trap原因，向各种处理任务发送通信 |
| `TrapInfo::new_handler()`：创建独立分发任务 | 是 | 删除 | \ |
| `TrapItem / TrapQueue / TrapWaitQueue`：缓存与处理请求 | 是 | 是 | 用于缓存trap，在trap_handler里不额外操作，在处理任务中再取出 |
| `IdleHandler / IdleHandlerQueue`：管理空闲分发任务 | 是 | 删除 | \ |
